

\# FormForge



\*\*FormForge: Design and Implementation of a Domain-Specific Language and Compiler for Automated Web Form Generation and Validation\*\*



\## 1. Introduction



FormForge is a small domain-specific language (DSL) and compiler developed as a Compiler Design Laboratory project.



It allows a user to describe a web form using a short FormForge source program. The compiler analyzes the source, checks its syntax and semantic rules, creates an intermediate representation, and generates an HTML form.



The compiler is implemented in C++. Its lexer and parser are handwritten; Lex, Flex, Yacc, Bison, and ANTLR are not used.



\## 2. Main Features



\- Lexical analysis and token recognition

\- Syntax analysis and parser

\- Abstract Syntax Tree (AST)

\- Semantic validation

\- Symbol table management

\- Intermediate Representation (IR)

\- HTML code generation

\- Lexical, syntax, and semantic error reporting

\- Multiple test programs

\- Browser-based HTML validation



\## 3. Technology Used



\- \*\*Programming language:\*\* C++

\- \*\*Target language:\*\* HTML

\- \*\*Compiler:\*\* g++

\- \*\*Terminal:\*\* Windows PowerShell

\- \*\*Browser:\*\* Modern web browser

\- \*\*Version control:\*\* Git and GitHub



\## 4. Supported FormForge Language



Supported field types:



\- `string`

\- `integer`

\- `email`



Supported constraints:



\- `required`

\- `min`

\- `max`



The `min` and `max` constraints are supported only for integer fields. Field names must be unique, and a form must contain at least one field.



\## 5. Example Program



Create a file named `program.form` with the following content:



```text

form StudentRegistration {

&#x20;   field name string required;

&#x20;   field age integer required min 17 max 60;

&#x20;   field email\_id email required;

&#x20;   submit "Register";

}

```



This program describes a form with a required name, a required age between 17 and 60, a required email field, and a Register button.

\## 7. Compilation



Open PowerShell in the project directory and run:



```powershell

g++ -Wall -Wextra main.cpp lexer.cpp parser.cpp symbol\_table.cpp semantic.cpp ir.cpp generator.cpp -o formforge

```



This compiles all C++ implementation files and creates the executable `formforge.exe`.



\## 8. Running FormForge



To compile the default source file, run:



```powershell

.\\formforge

```



To compile a particular source file, supply its path:



```powershell

.\\formforge tests\\valid.form

```



The program displays the results of lexical analysis, syntax analysis, AST construction, semantic analysis, symbol-table display, IR generation, and code generation.



\## 9. Generated Output



For the example program, the compiler generates:



```text

StudentRegistration.html

```



Open it in the default browser using:



```powershell

start StudentRegistration.html

```



The browser displays the form and applies the HTML validation attributes generated by FormForge.



A more complex source program can generate another output, such as `ContactForm.html`.



\## 10. Testing



The test programs cover:



\- Valid form compilation

\- Complex form compilation

\- Missing semicolon

\- Unsupported character

\- Invalid minimum/maximum relationship

\- Duplicate field

\- Invalid constraint type

\- Empty form

\- Integer outside the supported range

\- Duplicate constraint

\- Missing closing brace

\- Unterminated string literal



To run an individual test, use the appropriate path. For example:



```powershell

.\\formforge tests\\syntax\_error.form

```



Valid programs should complete compilation and generate HTML. Invalid programs should report an error and stop before target-code generation.



\## 11. Performance Measurement



Execution time was measured by running the compiled executable ten times for each of the two example programs.



The observed average invocation times were:



\- StudentRegistration: 38.435 ms

\- ContactForm: 33.970 ms



These results include process startup and file operations. They are specific to the test environment and are not a comparison with other compilers.



\## 12. Current Limitations



\- FormForge supports a deliberately small set of field types and constraints.

\- The generated forms use browser-side HTML validation.

\- Server-side form submission and data storage are not implemented.

\- FormForge does not have a separate interpreter or runtime.

\- Advanced styling and a large general-purpose language are outside the current scope.

\## 14. Conclusion



FormForge demonstrates how compiler-design concepts can be applied to a practical web-development task. A short program written in a custom language is analyzed and translated into a working HTML form. The project includes lexical analysis, parsing, AST construction, semantic analysis, symbol-table management, intermediate representation, code generation, and error testing.
